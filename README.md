# canairio-zone-analysis

**Rigorous statistical analysis of [CanAirIO](https://canair.io) air-quality
data, validated against official reference stations.**

[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](LICENSE)

*[Léeme en español](README.es.md)*

---

Low-cost air-quality sensors are cheap enough to deploy everywhere, and that
is their point. But a number without an error bar is not a measurement. This
project takes the raw stream from a CanAirIO network and answers a harder
question than "what does the sensor say?":

> **How much should we believe it — and compared to what?**

It pulls hourly data from InfluxDB, cleans it, runs non-parametric statistics
over it, and then validates every metric against the best reference available
for that location: a **nearby official monitoring station** when one exists,
and the CAMS/Copernicus model when none does. Each metric comes out labelled
`fiable` / `dudoso` / `no_fiable` with the correlation and bias that earned it
that label.

## Why this exists

We built it for Barakaldo Makers and it immediately found things we did not
know about our own network. The clearest example:

| | before | after |
|---|---|---|
| Zone PM2.5 | **0.33 µg/m³** | **5.36 µg/m³** |
| vs official station | rho 0.39, bias −95 % | rho 0.64, bias −19 % |

Six of our nine nodes had no PM sensor at all — a noise module and some gas
nodes — and the CanAirIO firmware publishes `0` for metrics whose sensor is
absent instead of omitting the field. Those zeros held **93 % of the data
points**, and a plain `mean()` across the zone drowned the three nodes that
were actually measuring. The zone had been reporting a sixteenth of the real
value, for weeks, with nothing flagging it.

That class of bug is invisible without a reference to check against. It is the
reason this project exists, and `docs/VALIDACION.md` documents five more of the
same kind.

## What it does

- **Two-stage zone aggregation.** Hourly mean *per sensor* first, then the
  **median across sensors** — so publication frequency does not weight the
  result and one miscalibrated node cannot drag a zone. Sensors reading exactly
  `0` across the whole window are excluded: they do not have that sensor.
- **Official reference chain.** For each zone (or each individual sensor), find
  its real position, then look for a reference-grade station within 25 km:
  first a local network, then [OpenAQ](https://openaq.org) worldwide, and
  CAMS/Copernicus only as a last resort.
- **Confidence labels per metric,** from Spearman correlation and relative bias
  against that reference — taking the *better verdict*, not merely the better
  correlation.
- **Correction factors** derived from the reference station, with a clear
  precedence so only one corrected figure is ever published.
- **Non-parametric statistics:** Mann-Kendall trend, Theil-Sen slope, 95 %
  confidence intervals, MAD outlier rejection. No assumption of normality.
- **Cross-sensor consensus:** each node against the median of its neighbours,
  which is how you catch a unit that has quietly drifted.
- **Pollution rose, CAQI, sustained episodes, hourly profiles,** and
  correlation with rain and pressure trends.
- **Nothing disappears silently.** Any metric that does not reach the analysis
  is reported in `discarded_metrics` with the reason and the figures.
- Optional **Telegram alerts** with persistence and hysteresis, and **static
  JSON output** for a web front-end.

Reports are generated by a **deterministic rules engine**, not an LLM. On the
hardware this was built for (an old CPU with no AVX), a local model needed
4.4 seconds per token — 30 to 45 minutes for one report. The rules engine is
instant, reproducible, and cannot hallucinate a measurement.

## Architecture

```
  CanAirIO network ──► InfluxDB ──► analysis engine ──┬──► JSON  (static site)
                                                       ├──► InfluxDB (history)
                                                       └──► Telegram (alerts)
                                         ▲
                  official stations ─────┤
                  CAMS / Copernicus ─────┤
                  Open-Meteo (weather) ──┘
```

One Flask service (`ai-bridge`) does the analysis and exposes a read-only HTTP
API. `docs/ARQUITECTURA.md` has the full pipeline, function by function.

## Quick start

Requires Docker, and an InfluxDB 1.x holding CanAirIO data (measurement
`fixed_stations_01`, tags `geo3` and `mac`).

```bash
git clone https://github.com/Barakaldo-Makers/canairio-zone-analysis.git
cd canairio-zone-analysis

cp .env.example .env
$EDITOR .env          # passwords, SITE_DIR, and your UID/GID

docker compose up -d --build

curl -s localhost:5000/health
curl -s localhost:5000/zones
```

Then run a full cycle and look at the result:

```bash
curl -s localhost:5000/run-cycle >/dev/null
bash scripts/check.sh            # readable summary of the first active zone
```

For real stations outside a supported local network, get a free
[OpenAQ key](https://explore.openaq.org/register) and put it in `.env` as
`OPENAQ_API_KEY`.

## HTTP API

| Endpoint | What it returns |
|---|---|
| `GET /health` | service status |
| `GET /zones` · `/zones/all` | active zones · every zone with its tier |
| `GET /analysis/<geo3>` | full analysis of a zone |
| `GET /analysis-sensor/<geo3>/<mac>` | full analysis of one sensor |
| `GET /analysis-sensors/<geo3>` | every sensor in a zone, individually |
| `GET /sensors` | all sensors with their latest readings |
| `GET /cross-validation/<geo3>` | consensus between neighbouring sensors |
| `GET /pollution-rose/<geo3>` | concentration by wind sector |
| `GET /compare/<geo3>` · `/compare-official/<geo3>` | vs CAMS · vs official stations |
| `GET /official-sources` | which reference each active zone is using |
| `GET /openaq-debug[/<geo3>]` · `/euskadi-debug[/<geo3>]` | reference diagnostics |
| `GET /run-cycle` · `/publish` | force a cycle · force publication |

> Per-metric statistics are published under **`statistics`**, not `metrics`.

## Adding your own official network

`euskadi.py` is a worked example: it discovers the Basque Government network
from its open-data portal, picks stations by distance **and by metric
coverage**, and averages them. Roughly 200 lines.

To add another network, write a module exposing:

```python
fetch_official_series(hours, lat=None, lon=None) -> (series, sources)
# series[metric]  = {epoch_hour_utc: value}   µg/m³, except CO in mg/m³
# sources[metric] = ["Station name", ...]
```

and add it to the chain in `fetch_official_any()` in `app.py`. `openaq.py`
follows the same contract. Pull requests adding networks are very welcome —
that is the most useful way to extend this.

## Honest limitations

- Built and tested against **InfluxDB 1.x with InfluxQL**. Not ported to 2.x.
- OpenAQ caps the search radius at **25 km**; zones with no station inside it
  fall back to the CAMS model, which is a model and not a measurement.
- The correction factors are a **single multiplicative factor** per metric.
  They do not model humidity, temperature or particle-size dependence.
- The EPA/Malm humidity correction is only applied where there is no reference
  station, because in our own deployment it pointed the *opposite* way to the
  official cabin — evidence that humidity was not what was biasing those units.
- Data from community sensors. **This is not an official air-quality source**
  and must not be used as one.
